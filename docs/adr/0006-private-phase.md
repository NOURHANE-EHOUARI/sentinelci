# ADR-0006: Private-phase operating mode

- Status: accepted; superseded in part by ADR-0011 (decision 1: the signing key stays on the laptop, not in a
  repository secret; decision 4: the private GHCR package is optional)
- Date: 2026-10-28

## Context

The repository stays private until the project is complete. Some planned controls behave differently for
private repositories:

- Keyless Cosign signatures embed the repository identity in a certificate recorded in the public Rekor
  transparency log, which would disclose the private repository.
- GitHub artifact attestations require a public repository on non-Enterprise plans.
- Uploading SARIF to GitHub code scanning is not included for private repositories on our plan.
- We stay on GitHub Free: branch protection is unavailable for this private repository, and Actions minutes
  are capped (2,000 per month).

## Decision

Until the repository goes public:

1. Sign with Cosign key pairs and do not upload to the public transparency log. The private key is a repository
   secret referenced only by the attest job (which never executes repository code). The public key is committed.
   *Superseded by ADR-0011, decision 7: any push or `workflow_dispatch` run can read a repository secret, so the
   key stays on the laptop and `make release` is the only signer during the private phase.*
2. Produce SLSA provenance as a Cosign in-toto attestation generated by the CLI from the workflow context.
3. Report results through PR comments, workflow artifacts and the SentinelCI dashboard.
4. Push CI images to a private GHCR package; Kubernetes demos use the kind cluster's local registry.
5. Budget Actions minutes: path filters, cached vulnerability databases, full image scans nightly on `main`.
6. Protect `main` by convention: changes only through reviewed PRs merged with a green CI (or, while Actions
   cannot run, a local `make check` report on the PR head), and a local pre-commit hook that refuses commits
   on `main`.

When the repository goes public, enable branch protection on `main` and switch to GitHub mode: keyless signing
via GitHub OIDC, GitHub artifact attestations in a reusable workflow (SLSA Build L3 target), SARIF upload to
code scanning, public GHCR images.

## Consequences

- One long-lived signing key exists during the private phase; it is rotated at the switch (since ADR-0011 it
  lives on the laptop, not in a repository secret).
- The CLI and Kyverno policies support both a key-based and a keyless attestor from the start.
- The migration itself is part of the project story (documented in this ADR and the changelog).
